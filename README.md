# IELTS Writing Scorer

一个用于 IELTS Writing Task 2（雅思大作文）的评分与教学 Skill，不适用于 Task 1 小作文。

评分校准依据是 1490 篇标注范文（Band 6 / 6.5 / 7 / 7.5 / 8 / 8.5 / 9）蒸馏出的六层知识资产。一次完整输出会给出四维评分、模块诊断、个性化 8+ 范文和逐句教学卡。

## 功能

### 校准评分

给出 TR、CC、LR、GRA 四项分数、总分、实际字数和一句话总评。评分内部依据 L1 到 L6 知识资产与同题型锚点校准，四项独立完成，LR 或 GRA 弱不会压低 TR；每个模块先写特征描述，再给分。规则编号、锚点和样本 id 只在内部使用，不写入交付报告。

评分前在内部检查字数、模板套作、偏题和输入完整性：字数少于 240 词、疑似模板套作或完全跑题会先按上限处理，只在评分卡里用一句话说明；没有题目时先要求补充题目，不做硬评。

### 模块诊断

- TR：思路诊断，检查立场、论点回应和论证推进，并给段落级重构建议。
- CC：逻辑结构图、逻辑不足定位和「原文 → 修正 → 说明」示范。
- 语言问题总览：LR 与 GRA 合并为一段，给主要问题类型、分数理由和逐句教学卡入口；具体纠错不在这里逐条展开。

### 范文教学

- 个性化 8+ 范文：270 到 300 词英文范文，保留用户立场与可用论点，只升级表达和论证完整度。
- 逐句教学卡：范文每句一张卡，六栏固定：中文示范句、我的原文、原句错误与不当、功能与观点提示、句式骨架与高分词伙、自检要点。语法错误、词汇错误、高频词伙提示和观点提示都整合在这里；教学卡不布置仿写、翻译、重组或拼装任务。

### 语言规范（人味化）

批改文件的讲解文字按「温柔、具体、有下文」输出：每条判断落到「句证 → 原因 → 改法 → 效果」，每张教学卡在纠错后给一句下一步注意点；中文讲解去除对偶升格、金句收尾、假深刻措辞等机器腔，英文范文同样过滤 AI 写作套路与万能模板句。细则见 `references/humanizer-rules.md`（适配自 Humanizer v3.1.0）。

### 输出格式

批改结果是一个 Markdown 文件，默认写入用户当前工作目录，文件名「雅思写作批改-<主题关键词>-<日期>.md」；用户指定路径或文件名时从其指定，环境无法写入文件时把同样的 Markdown 完整输出到对话。报告固定为四部分，顺序不变：评分卡 → 模块反馈（TR → CC → LR+GRA 语言问题总览）→ 个性化 8+ 范文 → 逐句教学卡。

排版约定：文件内不使用表格，也不出现 `|---|` 分隔行或以 `|` 分列的行；标题最多三级，列表符号统一用「-」，用户原句与范文正文用引用块；不加 Emoji，不加水平分隔线；内部编号、锚点、样本 id 和「规则命中」「锚点比对」等流程词不出现在文件里。写完在对话里只留文件位置、总分和最优先改的一项。

## 工作流

```
输入：用户作文 + 题目
│
├─ 0. 内部前置检查：字数 <240、疑似模板套作、完全跑题；无题目则先要求补题目
├─ 1. 审题前置：解析题目 → 检索 question-bank → 识别题型与主题
├─ 2. 四模块独立诊断：TR / CC / LR / GRA，先特征描述再给分
├─ 3. 锚点比对定分（内部）：与同题型相邻两档锚点对比，确认档位归属
├─ 4. 总分合成：四项平均，按官方规则取整（.25 → .5，.75 → 下一档）
├─ 5. 模块诊断：TR → CC → LR+GRA 语言问题总览
├─ 6. 范文教学：个性化 8+ 范文 → 逐句教学卡
└─ 7. 人味化校对：校对讲解文字与英文范文
```

输出顺序固定为：评分卡 → 模块反馈 → 个性化 8+ 范文 → 逐句教学卡。全部内容写入同一个 Markdown 文件。

## 使用

提交 Task 2 作文并要求打分、批改、提分诊断或高分范文时触发。建议把题目和作文一起提交；没有题目时 TR 无法评分，Skill 会先要求补充题目，不做硬评。讲解和反馈用中文，英文只出现在用户原句、范文正文、句式骨架与词伙中；教学卡里的范文句写中文。批改结果写入一个 Markdown 文件（默认在用户当前工作目录，文件名「雅思写作批改-<主题>-<日期>.md」），文件内不含表格；对话里只给文件位置与简短导语。

示例（简短的中文评测提示词，可整段复制）：

```text
请用雅思写作 Skill 批改下面这篇 Task 2 作文，按 TR、CC、LR、GRA 打分，把完整报告写成 Markdown 文件（不要表格），并告诉我最优先修改的一处。

题目：<粘贴题目>

作文：<粘贴作文>
```

## 输出示例

以一篇关于远程办公的作文为例，报告文件名是「雅思写作批改-远程办公-2026-10-08.md」。下面是报告的节选，包含评分卡、部分模块反馈、一个范文主体段和一张教学卡；完整报告还有其余模块反馈与范文每一句的教学卡。

```markdown
## 评分卡

- TR：6.5　CC：6　LR：6.5　GRA：6
- 总分：6.5（四项平均 6.25，按 .25 → .5 进位）
- 字数：268 词
- 总评：立场清楚，第二段论证停在观点句，缺少机制解释。

## 模块反馈

### TR（Task Response）

思路诊断：题目问远程办公对员工和雇主的影响，你的立场「利大于弊」在开头和结论里保持一致。第一个主体段的论点停在「在家工作更高效」，没有说明效率从哪里来，也没有回应雇主一侧。

段落级重构建议：第一个主体段按四步重写。「远程办公省下通勤时间（观点）→ 省下的时间投入需要连续专注的任务（机制）→ 这类任务的产出更稳定（例证）→ 雇主同样受益（回扣）。」

### CC（Coherence & Cohesion）

逻辑结构图：引言提出立场，主体段一写员工受益，主体段二写雇主受益，结论重复引言。两个主体段之间用 `Besides` 衔接，读不出推理关系。

逻辑不足定位：论点与例证脱节。第一个主体段说「在家更高效」，紧跟的例子却是「不用挤地铁」；通勤时间减少不等于工作效率提高，例子没有支撑论点。修正示范：把例子换成「避开打断、连续投入两小时」，例证就能直接回应效率这个论点。

### 语言问题总览（LR + GRA）

LR 6.5：词伙基本准确，`make more efficiency`、`take care of my work` 这类搭配偏口语。GRA 6：简单句准确，复杂句尝试少，第二个主体段的定语从句有省略错误。具体到句的语法与词汇纠错见下面的逐句教学卡。

## 个性化 8+ 范文

> Working from home changes how employees use their time. When commuting disappears from the daily routine, the hours it used to take can go into tasks that need sustained focus, so these tasks are less likely to be broken into fragments. Employers gain as well, because steady progress on them is easier to measure than hours spent at a desk.

## 逐句教学卡

**【主体段1 · 第2句：机制解释句】**

- 中文示范句：通勤从日常安排里消失之后，原本花在路上的时间可以投入需要持续专注的任务，这些任务因此不容易被切碎。
- 我的原文：
  > Working from home can make more efficiency, because people don't need to go to office.
- 原句错误与不当：`make more efficiency` → `improve efficiency`（搭配）；`go to office` → `go to the office`（冠词）。论证上，通勤时间省下来不自动等于效率提高，中间少了「时间被用到哪里」这一步。改法：把省下的时间交给需要连续专注的任务，让因果链完整。
- 功能与观点提示：这句承担机制解释，把主题句「远程办公提高效率」推进到效率的来源。本题还可以从雇主一侧补一句：产出更稳定之后，用人考核会从工时长转向结果。
- 句式骨架与高分词伙：骨架 `When [变化] frees up [时间], [主体] can [动作], so [结果]`。词伙：`sustained focus`（持续专注）、`deep work`（深度工作）。它们把「效率」写成一个可解释的过程，比 `more efficiency` 具体。
- 自检要点：写因果句时，because 或 so 后面的内容是不是比前半句更具体？如果只是把「效率高」换成「省时间」，中间的一步还没有补上。
```

节选结束。教学卡按范文句序排列，每句一张，字段与示例一致。

## 知识资产

| 层 | 文件 | 内容 | 规模 |
|---|---|---|---|
| L1 评分规则库 | `references/band-rules.md` | TR/CC/LR/GRA × 7 档判别规则 + 6 组相邻档 Delta + 半分档 | 全文必读 |
| L2 锚点范文库 | `references/anchors/<题型>.md` | 每「分数 × 题型」2 到 3 篇代表作 + 逐项评语 | 5 个题型文件 |
| L3 错误模式库 | `references/error-patterns.md` | 高频失分模式 + 母语负迁移标签 | 全文必读 |
| L4 语言资产库 | `references/language-assets.md` | 高分句式、衔接、论证展开套路 | 按题型/主题检索 |
| L5 观点库 | `references/viewpoint-bank/` | 8+ 样本的论点与展开链条 | 248 条 / 10 主题 |
| L6 主题词库 | `references/topic-vocab/` | 8+ 样本高频词伙 + 原文例句 | 485 条 / 10 主题 |
| 题目解析库 | `references/question-bank.md` | 关键词拆解、隐含限定、审题失误、双边观点池 | 56 个高频题簇 |

L4、L5、L6 分别服务于教学卡的句式骨架、观点提示和高分词伙；观点、词伙和审题要点都来自库内，库里没有对应主题时改用通用表达，不编造内容。所有库内编号与来源样本 id 只在内部检索和复核时使用，不写入报告。

## 纪律条款

1. 分数必须可追溯（内部）：每项分数由规则命中和锚点比对内部推出，报告不展示内部编号。
2. 四项独立评分：LR/GRA 分开评分，文字诊断可以合并呈现，模块之间互不牵连。
3. 诊断先于分数：每个模块先写特征描述，再给分。
4. 禁止编造库内容：观点、词伙、审题要点和错误诊断来自 references/ 或对原文的直接分析。
5. 修改保持原意：范文重写只升级表达和论证完整度，不替换用户观点。
6. 教学卡只做讲解：不布置仿写、翻译、重组或拼装任务。

## 安装

把 Skill 目录复制到 Codex 的 skills 目录：

```powershell
Copy-Item -Recurse .\ielts-writing-scorer $HOME\.codex\skills\
```

其他支持 Skill 的环境，把 `ielts-writing-scorer/` 当作 Skill 根目录即可。Skill 名称在 `SKILL.md` 的 frontmatter 中定义为 `ielts-writing-scorer`。

## 数据来源与限制

- 知识资产蒸馏自 1490 篇公开标注范文的 7 个分数档（训练集 1193 篇）。
- 分数标签复制自来源页面，本 Skill 不对来源语料重新打分。
- 8.5 档与部分半分档来源以自动评分为主；L2 锚点与 L1 规则对这类来源从严使用。
- references/ 中的来源样本 id（如 `B8-DIS-001`）只用于内部溯源与复核，不写入批改报告；原始语料不随本 Skill 发布。
