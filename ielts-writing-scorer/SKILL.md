# 雅思大作文评分与教学 Skill（Task 2）

## 一、工作前提

- **三大引擎**：校准评分（四维分数 + 总分）、模块化反馈（诊断 + 修改建议）、范文教学（个性化范文 + 拆解练习）。本文件把三者串成一个闭环：评分诊断是反馈的输入，诊断 + 原文是范文的输入。
- **校准基础**：references/ 下六层知识资产（L1–L6）蒸馏自 1490 篇标注语料的训练集（1193 篇）。
- **盲测封存纪律**：`sample-library/blindtest/`（297 篇）只供任务三校准测试；评分、蒸馏、调参环节一律不读取。
- **知识资产边界**：本文件只含流程、模板与检索指引，不含任何知识资产内容；references/ 已由任务二填充（v2：L5/L6 全量蒸馏并按主题拆分，2026-10-07，来源为训练集 1186 篇）。当某库无对应条目（如观点库未覆盖某主题）时，明确输出「暂未收录」，禁止编造规则编号、观点编号、词伙来源或锚点内容。
- **输出语言**：讲解与反馈用中文；英文只出现在原句、修正句、范文与词伙中。

## 二、流程最前端：边界情形检查（优先于一切评分）

以下情形触发官方罚分规则，先于四模块评分检查，结论置顶输出：

| 情形 | 处理 |
|---|---|
| 字数严重不足（< 240 词） | 先报告实际字数与缺口，给出分数上限，再进入常规流程 |
| 疑似背模板套作 | 指出与题目无关的万能句、可套任何题的连接词段落，下调 TR/CC 上限，反馈重心转为「用自己的话重建论证」 |
| 完全跑题 | TR 压至低档；范文环节先做审题重定向，再给范文 |

## 三、非标准输入处理

| 输入 | 处理 |
|---|---|
| 未附题目 | 要求补充题目；**无题目则 TR 无法评分，明确拒绝硬评**；CC/LR/GRA 可在用户确认后先行评估 |
| 只提交单段 | 按段批改，并注明无法评估全文 CC |
| 手写照片 | 先转写再批改，转写不确定处逐条列出请用户确认 |
| 明显非考场限时作品 | 注明本分数为精修作品评估，可能与限时考场表现存在偏差 |

## 四、评分主流程

输入：用户作文 + 题目。进入以下六步前，先完成第二、三两节的前置检查。

1. **审题前置 → 识别题型与主题**：先解析题目，再读文章。按题目关键词/题型检索 `references/question-bank.md`：命中则调用库内审题要点；未命中则现场生成审题要点（**关键词圈定、隐含限定、双边观点池**）并追加回库。随后判定题型（观点/讨论/利弊/报告/双问题）与主题（十类），定位 `references/anchors/<题型>.md` 与 `references/language-assets.md` 对应主题段；加载 `references/band-rules.md`（L1）与 `references/error-patterns.md`（L3）全文。
2. **四模块独立诊断**：TR/CC/LR/GRA 逐项对照 L1 规则逐条检查、对照 L3 错误模式扫描；每个模块**先给「特征描述」再给分**。
3. **锚点比对定分**：与同题型相邻两档锚点对比，确认「高于 6 锚点、不及 7 锚点」式的档位归属，再定 ±0.5。
4. **总分合成**：四项平均，按官方规则取整（.25 → .5，.75 → 下一档）。
5. **生成模块化反馈**：按下文「模块化反馈模板」输出。
6. **生成个性化范文与拆解练习**：按下文「范文与拆解教学」输出。

## 五、纪律条款（不可违反）

1. **分数必须可追溯**：每项分数由「规则命中情况 + 锚点比对」推出，输出中引用具体命中的规则条目（如 `L1-TR-3.2`）与锚点样本 id；不允许无依据的「整体感觉分」。证据不足（无题目、库未填充）时降级为「暂缺」并说明原因。
2. **四项独立评分**：禁止模块间污染——不得因为 LR 弱就压低 TR。中国考生最常见的误判就是语法弱牵连内容分；逐项封闭完成后再汇总，输出前自查一遍。
3. **诊断先于分数**：每个模块先写特征描述，后给分；禁止先拍分再找理由。
4. **禁止编造库内容**：观点、词伙、锚点、审题要点一律来自 references/ 并注明编号；库缺即明说「暂未收录」。
5. **修改保持原意**：范文重写与句式升级只升级表达，禁止借机替换用户观点。
6. **盲测集零接触**：任何情况下不读取 `sample-library/blindtest/`。

## 六、输出模板：模块化反馈

**输出总顺序**：边界情形标注（若触发）→ 评分卡 → 优先修复清单 → 四模块反馈（TR → CC → LR → GRA）→ 原文 ↔ 范文对照表 → 个性化 8+ 范文 → 逐句教学卡 → 三级练习 → 拼装指南。

### 6.1 评分卡

| TR | CC | LR | GRA | 总分 | 字数 | 一句话总评 |
|---|---|---|---|---|---|---|

四项独立分数 + 取整后的总分 + 实际字数 + 不超过 30 字的总评。

### 6.2 优先修复清单（按提分 ROI 排序，置于一切建议之前）

| 优先级 | 问题 | 类别 | 预计影响 | 修复动作 |
|---|---|---|---|---|

排序规则：

1. **封顶性问题**（偏题、未表态、字数不足等触发分数上限者）永远排第一；
2. **系统性问题**（全文性模式：连接词机械化、句句简单句）；
3. **局部性问题**（个别搭配错误、零星语法错）。

每条注明「修复此项预计影响哪个模块的多少分」，如「回应题目的 only 限定 → TR 上限从 6.5 解除」。

### 6.3 TR（Task Response）

1. **思路诊断**：立场是否明确一贯；每段论点是否直接回应题目关键词；论证是否有具体化推进；例证是否有效。
2. **思路修改建议**：段落级重构方案，给出改写后的论证链（观点 → 机制 → 例证 → 回扣）。
   > 例：第二段目前停在「科技让人疏远 → 因为大家玩手机」。建议改为：观点（过度依赖即时通讯削弱了深度交流能力）→ 机制（碎片化对话替代了需要持续关注与共情的面对面交谈）→ 例证（家庭聚餐中各自刷手机的场景 / 浅层社交与孤独感的研究指向）→ 回扣（因此技术本身中性，使用方式决定了人际质量）。
3. **观点库调用**：先读 `references/viewpoint-bank.md`（索引）定位主题，再读取 `references/viewpoint-bank/<主题>.md`（L5 分文件）检索条目，给出 2–3 条用户没想到的高分角度，注明库内编号（如 `EDU-01`）与来源样本分数。库中无该主题时明确说明「该主题暂未收录」。

### 6.4 CC（Coherence & Cohesion）

1. **逻辑结构图**：先用一句话概括每段功能，画出全文论证链条，让用户直观看到断裂点。
2. **逻辑不足定位**：逐条列出并归类——跳跃（结论先于论据）/ 循环论证 / 论点与例证脱节 / 衔接词机械化（堆砌 Firstly、Moreover 而句间无真实逻辑关系）/ 指代断裂（this、they 指代不明）。
3. **修正示范**：每一处不足给「原文 → 修正文 → 修正逻辑说明」三件套；涉及段落顺序问题的，给出重排后的段落序列及理由。

### 6.5 LR（Lexical Resource）

1. **不恰当词汇修正表**（表格输出）：

   | 原文 | 问题类型 | 修正 | 说明 |
   |---|---|---|---|
   | learn knowledge | 搭配错误 | acquire / gain knowledge | learn 不接 knowledge，中式直译 |
   | very important | 词汇贫乏 | crucial / pivotal | 缺乏精确性 |

   问题类型限定为：搭配错误 / 词性误用 / 中式直译 / 语义不准 / 语域不当（口语词入文）/ 重复用词。
2. **主题高频高级词汇调用**：先读 `references/topic-vocab.md`（索引），再读取 `references/topic-vocab/<主题>.md`（L6 分文件）检索同主题词块，给出 8–12 个高分词伙（collocation 优先于单词），每个附一句**结合本题语境**的例句——例句必须服务于本文改写，不给与题目无关的孤立例句。词伙附带来源样本的，标注「出自某篇 8.5 分范文」；库中无该主题时明确说明。

### 6.6 GRA（Grammatical Range & Accuracy）

1. **语法错误逐条清单**（表格输出，穷尽全部错误，不抽样）：

   | # | 原文 | 错误类型 | 修正 | 一句话解析 |
   |---|---|---|---|---|
   | 1 | Government should takes measures | 主谓一致 | should take | 情态动词后接动词原形 |

   错误类型标签统一为：主谓一致 / 时态 / 单复数 / 冠词 / 词性 / 句子残缺 / run-on / 悬垂结构 / 从句误用 / 标点。
2. **句式升级**：挑出文中 3–5 个语法正确但表达平庸的句子，各给 2 个升级版本（稳妥版 + 出彩版），并说明升级点（如简单句合并为分词状语结构、引入让步状语从句、被动语态调整信息焦点）。升级必须保持用户原意。

## 七、输出模板：范文与拆解教学

### 7.1 范文生成原则

- **个性化 = 升级而非另写**：保留用户的立场与可用论点，用第六节的修改意见重写为一篇 270–300 词的 8+ 范文。用户学的是「我的想法怎么写好」，而不是背诵一篇陌生范文。
- 若原文思路存在根本性缺陷（如偏题），在范文前先用一段话说明改动逻辑，再给出范文。

### 7.2 原文 ↔ 范文对照表（置于范文之前）

| 原文句 | 范文对应句 | 一句话改动原因（标注属于 TR/CC/LR/GRA 哪类） |
|---|---|---|

被完整保留、未改动的句子也列出并标注「保留」——知道自己哪里已经写对了同样重要。

### 7.3 逐句拆解教学卡

把范文按功能拆成教学单元：引言 2 句（题目转述 + 立场）、每个主体段 4–5 句（主题句 → 解释 → 例证 → 回扣）、结论 1–2 句。**每一句输出一张教学卡**，六栏固定：

```markdown
**【主体段1 · 第2句：机制解释句】**
- 范文原句：This is largely because fragmented online exchanges displace the
  sustained, empathetic conversations that build genuine closeness.
- 功能：解释主题句成立的原因，是论证链的引擎。
- 句式骨架：This is largely because + [A 替代/削弱了 B]，其中 B 用定语从句补充价值。
- 中文回译提示：这很大程度上是因为碎片化的线上交流取代了……
- 仿写练习：用同样骨架解释「远程办公削弱团队凝聚力」。提示词：remote work / spontaneous collaboration / trust
- 自检要点：because 后的原因是否比主题句更具体？若只是换个说法则为无效解释。
```

### 7.4 三级练习（由局部到整体）

1. **句式仿写**：各教学卡已内置——给定新语境，套用骨架。
2. **中译英回译**：给范文的 3 个关键句中文版，要求回译，附参考答案与常见译法对比。
3. **段落重组**：取某一个主体段的句子打乱编号，要求排序并说明理由（训练 CC 意识）。

### 7.5 拼装指南（成文训练）

1. 先写各段主题句，通读检查是否覆盖了题目的所有关键词；
2. 逐段填充解释与例证，填完后检查段内每句是否都能回答「这句如何支撑主题句」；
3. 段落间检查衔接：相邻段之间靠语义推进而非连接词；
4. 通读全文，对照 GRA 常见错误清单自查（主谓一致、单复数、时态）；
5. 最后写引言与结论（引言在思路定稿后写最省力）。

## 九、运行时增强（接口预留，依赖真实使用数据积累）

### 9.1 个人成长档案（`user-profile.md`，存于用户工作目录而非本 Skill 内）

- **记录**：历次分数曲线、个人高频错误画像（在 L3 错误模式库中命中最多的条目）、历史建议采纳情况。
- **定向使用**：练习优先从个人高频错误出题；范文句式难度锚定在用户当前 GRA 水平 +0.5 档；反馈开头报告与上次的对比（如「对比上次：冠词问题已改善，指代断裂仍出现 3 次」）。
- **维护**：首次使用时创建；每次批改结束追加一条记录。

### 9.2 练习批改闭环

- 练习配参考答案 + 常见错误译法对比；用户提交练习答案后二次批改，结果回写成长档案。
- 练习不自判对错，则不构成训练闭环；首次输出时应告知用户可回传练习作答，等待二次批改。
