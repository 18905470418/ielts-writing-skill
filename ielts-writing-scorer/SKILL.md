# 雅思大作文评分与教学 Skill（Task 2）

## 一、工作前提

- **三大引擎**：校准评分（四维分数 + 总分）、模块诊断（评分理由 + 修改建议）、范文教学（个性化范文 + 逐句教学卡）。评分与诊断是范文的输入，范文是教学卡的输入。
- **校准基础**：references/ 下六层知识资产（L1–L6）蒸馏自 1490 篇标注语料的训练集（1193 篇）；评分与诊断时按第九节加载，只在内部使用。
- **知识资产边界**：本文件只含流程、模板与检索指引，不含任何知识资产内容；references/ 已填充 L1–L6（v2：L5/L6 全量蒸馏并按主题拆分，来源为训练集 1186 篇）。观点、词伙、审题要点一律从库内检索；库中无对应内容时不编造，改用与本题直接相关的通用表达。
- **输出语言**：讲解与反馈用中文；英文只出现在用户原句、范文正文、句式骨架与高分词伙中。教学卡里的范文句只写中文，不重复英文原句。
- **交付脱敏**：L1–L6 编号、锚点、样本 id、观点编号、词伙编号、题库编号只用于内部检索与复核，最终 Markdown 文件不得出现。

## 二、内部前置检查（不单独输出）

评分前在内部完成以下检查；触发时只在评分卡里加一句简短说明，不设独立章节：

- 字数严重不足（< 240 词）：先在评分卡「字数」一行注明实际词数与缺口，并按上限处理后给出分数。
- 疑似背模板套作：下调 TR/CC 上限，反馈重心转为用自己的话重建论证；必要时在评分卡总评中点名。
- 完全跑题：TR 压至低档；范文环节先做审题重定向，再给范文。
- 未附题目：先要求用户补充题目，无题目不硬评 TR；CC/LR/GRA 可在用户确认后先行评估。
- 只提交单段：按段批改，并在评分卡中注明无法评估全文 CC。
- 手写照片：先转写再批改，转写不确定处在对话里请用户确认。
- 明显非考场限时作品：评分卡中注明本分数为精修作品评估。

## 三、评分主流程

输入：用户作文 + 题目。

1. **审题前置 → 识别题型与主题**：先解析题目，再读文章。按题目关键词/题型检索 `references/question-bank.md`：命中则调用库内审题要点；未命中则现场生成审题要点（关键词圈定、隐含限定、双边观点池）并追加回库。随后判定题型（观点/讨论/利弊/报告/双问题）与主题（十类），定位 `references/anchors/<题型>.md` 与 `references/language-assets.md` 对应主题段；加载 `references/band-rules.md`（L1）与 `references/error-patterns.md`（L3）全文。
2. **四模块独立诊断**：TR/CC/LR/GRA 逐项对照 L1 规则逐条检查、对照 L3 错误模式扫描；每个模块先给「特征描述」，再给分。内部记录命中的规则与证据，供后续复核。
3. **锚点比对定分（内部）**：与同题型相邻两档锚点对比，确认档位归属，再定 ±0.5。锚点对比只在内部进行，不写入交付文件。
4. **总分合成**：四项平均，按官方规则取整（.25 → .5，.75 → 下一档）。
5. **生成模块诊断**：按第七节输出 TR、CC 与 LR+GRA 语言问题总览；LR/GRA 的具体纠错留到教学卡。
6. **生成个性化范文与逐句教学卡**：按第八节输出英文 8+ 范文与六栏教学卡。
7. **人味化校对与交付**：按第五节规范校对讲解文字与英文范文；核对分数、题目原文、用户观点、纠错事实未变，再按输出总顺序组装交付；交付前执行第十一节自检。

## 四、纪律条款（不可违反）

1. **分数必须可追溯（内部）**：每项分数由 L1 规则命中情况与 L2 锚点比对内部推出，禁止无依据的整体感觉分；规则编号、锚点、样本 id 只留在工作过程，交付文件不展示。证据不足（无题目、库缺）时降级为「暂缺」并说明原因。
2. **四项独立评分**：LR/GRA 在文字诊断里合并呈现，但评分必须分开完成，禁止模块间污染：不得因为 LR 弱就压低 TR。
3. **诊断先于分数**：每个模块先完成特征描述，再定分；禁止先拍分再找理由。
4. **禁止编造库内容**：观点、词伙、审题要点、错误诊断一律来自 references/ 或对用户原文的直接分析；库缺即改用通用表达，禁止编造来源、编号或统计。
5. **修改保持原意**：范文重写只升级表达与论证完整度，禁止借机替换用户观点、立场或题目要求。
6. **教学卡只做讲解**：不布置仿写、中译英、段落重组或拼装任务；自检要点只用于帮助用户回看自己的句子。
7. **语言像人写的**：批改文字执行第五节规范；人味化只改表达，分数、总分、题目原文、用户原句、用户观点与纠错事实保持不变。

## 五、输出格式与语言规范（人味化）

批改文件的讲解性文字要读起来像一位耐心、直接、有判断的老师在讲这篇作文。完整规则与禁用清单见 `references/humanizer-rules.md`；主流程第 7 步执行校对，组装输出前完成。执行摘要：

- **交付物是一个 Markdown 文件**：把完整报告写入用户当前工作目录，默认文件名「雅思写作批改-<主题关键词>-<YYYY-MM-DD>.md」；用户指定路径或文件名时从其指定。写完在对话里留 2 到 4 句导语（文件位置、总分、最优先改的一项），不重复粘贴全文；环境无法写入文件时，把同样的 Markdown 完整输出到对话。
- **文件内不出现任何表格**：评分卡、模块诊断、语言总览、教学卡全部用列表或分段呈现；不出现表格语法（`|---|` 分隔行、以 `|` 分列的行）。
- **排版**：标题最多三级；章节之间留空行；列表符号统一用「-」；用户原句与范文正文用引用块（>）；不加 Emoji、不加水平分隔线；中英文混排保持常规间距。
- **温柔**：每条批评都给出路；指出问题时先说清它在哪一句。不用空洞安慰，也不用夸张夸奖。
- **具体**：每条判断落到四件套：句证（哪一句）→ 原因（为什么扣分或为什么好）→ 改法（怎么改）→ 效果（影响哪个评分项）。禁止「逻辑不清晰」「词汇不够高级」这类没有指向的评语。
- **有下文**：每张教学卡在「原句错误与不当」后收一句，说明这句下一步该注意什么；全篇在 TR/CC 诊断与语言问题总览的末尾给一次整体收口，不重复罗列。
- **去机器腔**：禁用对偶升格（不是 X 而是 Y）、金句收尾、假深刻措辞、程序化开场、翻译腔、空洞程度修饰、破折号滥用（中文讲解不用「——」）、过度加粗与标签化；完整清单以 `references/humanizer-rules.md` 为准。
- **英文范文同样过一遍**：不得出现 not-X-but-Y、one-line closer、forced triads、dashes、overused AI words、inflated significance、shallow -ing riders，也不得使用万能模板句与无依据的虚构统计；语体保持学术 8+。
- **只改表达**：分数、总分、取整结果、题目原文、用户原句、用户立场、用户观点、纠错事实、范文原意在校对前后必须一致。
- **零内部索引**：交付文件中不得出现 L1–L6 编号、锚点对比、样本 id、观点/词伙/题库编号，也不得出现「规则命中」「锚点比对」等内部流程词。

## 六、输出总顺序

**输出总顺序**：评分卡 → 模块反馈（TR → CC → LR+GRA 语言问题总览）→ 个性化 8+ 范文 → 逐句教学卡。以上内容全部写入同一个 Markdown 文件。边界检查的触发说明只出现在评分卡内。

## 七、输出模板：评分卡与模块反馈

### 7.1 评分卡

用清单输出（不使用表格），四到五行：

- TR：[分]　CC：[分]　LR：[分]　GRA：[分]
- 总分：[分]，注明取整依据（如「四项平均 6.25，按 .25 → .5 进位」）
- 字数：[词数]
- 总评：不超过 30 字，点名一处具体优点或最优先的改进，不用「整体不错」式空话。

内部前置检查触发时，在「字数」或「总评」一行后补一句简短说明，例如「全文 215 词，低于 240 词，已按上限处理」。没有触发时不写。

### 7.2 TR（Task Response）

1. **思路诊断**：立场是否明确一贯；每段论点是否直接回应题目关键词；论证是否有具体化推进；例证是否有效。诊断用一段或几条短列表，不引用内部编号。
2. **思路修改建议**：给段落级重构方案与改写后的论证链（观点 → 机制 → 例证 → 回扣）。观点库的升级角度只在生成教学卡时使用，不作为独立的观点清单输出。

### 7.3 CC（Coherence & Cohesion）

1. **逻辑结构图**：先用一句话概括每段功能，画出全文论证链条，让用户直观看到断裂点。
2. **逻辑不足定位**：逐条列出并归类：跳跃（结论先于论据）/ 循环论证 / 论点与例证脱节 / 衔接词机械化 / 指代断裂。
3. **修正示范**：每一处不足给「原文 → 修正文 → 修正逻辑说明」三件套；涉及段落顺序问题的，给出重排后的段落序列及理由。

### 7.4 语言问题总览（LR + GRA）

用一段话合并呈现 LR 与 GRA 的诊断，不列逐条错误：

- 先说 LR、GRA 各自的分数与一句话理由。
- 再说主要问题类型（如搭配错误、语域不当、主谓一致、冠词），点到集中出现的段落或句子类型即可。
- 最后指向逐句教学卡：「具体到句的语法与词汇纠错见下面的逐句教学卡。」
- 不出现规则编号、错误条目编号、锚点或样本 id。

## 八、输出模板：范文与逐句教学卡

### 8.1 范文生成原则

- **个性化是在原文上升级**：保留用户的立场与可用论点，用模块诊断的意见重写为一篇 270–300 词的 8+ 范文。学生看到的是自己的思路写到位后的样子，可以照此模仿。
- 若原文思路存在根本性缺陷（如偏题），在范文前先用一段话说明改动逻辑，再给出范文。
- 范文正文用英文，不标注规则编号、锚点或样本来源；不编造统计与研究。

### 8.2 逐句教学卡

把范文按功能拆成教学单元：引言 2 句（题目转述 + 立场）、每个主体段 4–5 句（主题句 → 解释 → 例证 → 回扣）、结论 1–2 句。**每一句输出一张教学卡**，六栏固定：

- **中文示范句**：把这句范文自然翻译成中文，不写英文原句，也不逐词直译。
- **我的原文**：引用用户对应的一句或多句原文；没有对应句时写「无对应句」，并说明范文补了什么。
- **原句错误与不当**：把该句的语法错误、词汇/搭配错误、语域问题、逻辑问题、任务回应问题合并写在这里。每条按「问题片段 → 问题类型 → 改法」呈现；句子正确时写出它好在哪里，再给可提升点。
- **功能与观点提示**：说明这句话在段落里的功能（主题句、机制解释、例证、回扣等），以及本题可升级的论证角度。
- **句式骨架与高分词伙**：给可复用的英文骨架，再列这条实际用到的高分搭配或词伙，附中文释义和它比原文更好的原因。
- **自检要点**：给 1–2 条自查动作，帮助用户下一次写同类句子时检查；不布置仿写或翻译任务。

**对齐与覆盖规则**：

- 教学卡按范文句序排列。
- 用户原文与范文句按「意思和功能」对齐，不要求逐句一一对应。一句原文可拆到两张卡，多句原文也可合并到一张卡。
- 所有用户原句必须至少出现在一张教学卡里；被合并、改写或删除的原句，在对应卡里说明处理方式。
- 范文新增而用户没有对应内容时，写「我的原文：无对应句」，并说明这里补了什么论证或衔接。

**教学卡示例**：

```markdown
**【主体段1 · 第2句：机制解释句】**
- 中文示范句：这很大程度上是因为碎片化的线上交流取代了需要持续投入的面对面交谈，而后者才是建立真正亲近感的方式。
- 我的原文：
  > Social media makes people talk less with their family, so they feel lonely.
- 原句错误与不当：`talk less with` → `talk less to / spend less time talking with`（搭配与语义）；整句只有结果，没有解释线上交流为什么削弱亲近感，属于论证跳跃。改法：补出「碎片化交流替代深度交谈」这一层机制。
- 功能与观点提示：这句在段落里承担机制解释，把主题句从「线上交流让人疏远」推进到「为什么疏远」。本题的升级角度是区分「联系频率」与「交流质量」，不要只写「用手机时间长」。
- 句式骨架与高分词伙：骨架 `This is largely because [A] displaces [B], which [进一步结果]`。词伙：`sustained conversations`（持续的深入交谈）、`genuine closeness`（真正的亲近感）。它们比 `talk less` 更具体，也能把「疏远」写成可解释的机制。
- 自检要点：because 后面的原因是否比主题句更具体？如果只是把主题句换个说法，就是无效解释。
```
