# Obsidian 版输出格式（obsidian-format）

适用范围：用户选择 Obsidian 版时，组装输出前全文必读。本文件只管呈现方式；评分、字数、模块诊断、范文与六栏教学卡仍按 `SKILL.md` 第七、八节生成，两版内容逐项一致。

## 一、文件骨架

固定顺序：

1. YAML frontmatter
2. H1 标题
3. 评分卡 callout
4. TR callout
5. CC callout（含 Mermaid 逻辑结构图）
6. 语言问题总览 callout
7. 个性化 8+ 范文 callout
8. 逐句教学卡 callout（每句一张）

- 四部分与每张教学卡的标题都由 callout 首行承担，不再另写重复的二级或三级标题；模块反馈的分组由连续的 TR / CC / 语言问题总览三块 callout 承担。
- callout 内的内容格式与通用版相同（列表、引用、段落），逐行加 `>` 前缀；callout 之间留一个空行。
- 全文不使用表格、不加 Emoji、不加水平分隔线、不出现内部编号。

## 二、frontmatter 规范

```yaml
---
日期: 2026-10-08
题型: 观点
主题: 远程办公
总分: 6.5
TR: 6.5
CC: 6
LR: 6.5
GRA: 6
字数: 268
tags:
  - 雅思写作
  - 批改
---
```

- 日期写批改当天，格式 `YYYY-MM-DD`。
- 题型写中文：观点 / 讨论 / 利弊 / 报告 / 双问题。
- 分数与字数写数字，不带单位；主题用题目关键词，值里不出现 `:`、`#` 等 YAML 特殊字符，需要时用引号包裹。
- tags 固定「雅思写作」「批改」两项。
- frontmatter 只放公开信息，不写规则编号、锚点、样本 id。

## 三、H1 标题

```markdown
# 雅思写作批改｜<主题关键词>
```

主题与 frontmatter 的「主题」保持一致。

## 四、callout 映射

| 内容 | callout 首行 |
|---|---|
| 评分卡 | `> [!info] 评分卡` |
| TR | `> [!note] TR（Task Response）` |
| CC | `> [!tip] CC（Coherence & Cohesion）` |
| 语言问题总览 | `> [!warning] 语言问题总览（LR + GRA）` |
| 个性化 8+ 范文 | `> [!quote] 个性化 8+ 范文` |
| 逐句教学卡 | `> [!example]+ <卡片标题>` |

- 教学卡的 `+` 表示默认展开、可折叠；卡片标题沿用通用版的命名（如「主体段1 · 第2句：机制解释句」），直接写在 callout 首行，不再加 `**` 加粗。
- callout 标题不加 Emoji，不加编号。
- 卡内六栏与顺序不变：中文示范句、我的原文、原句错误与不当、功能与观点提示、句式骨架与高分词伙、自检要点。
- 教学卡内引用用户原句用嵌套引用块：

```markdown
> - 我的原文：
>   > Working from home can make more efficiency, because people don't need to go to office.
```

## 五、Mermaid 逻辑结构图

- 只在 CC callout 内出现一处 `mermaid` 代码块，画全文论证链。
- 节点标签加双引号，短语不超过 12 字；段落功能依次连成实线箭头。
- 衔接薄弱或断裂处用虚线箭头并标注原因（如「衔接弱」「缺回扣」）。
- 代码块语言标记写 `mermaid`，每行以 `>` 前缀，围栏闭合。

````markdown
> [!tip] CC（Coherence & Cohesion）
> 逻辑结构图：
> ```mermaid
> flowchart TD
>   A["引言：立场"] --> B["主体段一：员工受益"]
>   B -. "衔接弱" .-> C["主体段二：雇主受益"]
>   C --> D["结论：重申立场"]
> ```
> 逻辑不足定位：……
> 修正示范：……
````

## 六、文件名与落盘

- 默认文件名「雅思写作批改-<主题关键词>-<YYYY-MM-DD>-obsidian.md」。
- 默认写入用户当前工作目录；用户指定路径或 vault 目录时从其指定，文件名未指定时才用默认名。
- 环境无法写入文件时，把同样的 Markdown 完整输出到对话。
- 写完在对话里留 2 到 4 句导语（文件位置、总分、最优先改的一项），不重复粘贴全文。

## 七、组装前自检

- [ ] frontmatter 以 `---` 开始、以 `---` 结束，键值可被 YAML 解析，tags 为列表。
- [ ] H1 标题与 frontmatter 主题一致。
- [ ] 每个 callout 的每一行都带 `>` 前缀；callout 类型与映射表一致。
- [ ] 教学卡用 `[!example]+`，默认展开可折叠；六栏齐全、顺序不变。
- [ ] Mermaid 只用一处、语言标记正确、节点标签加引号、围栏闭合。
- [ ] 无表格行、无 Emoji、无水平分隔线、无内部编号。
- [ ] 与通用版相比，分数、字数、模块诊断要点、范文与教学卡逐项一致。
